## อยากลองกดเล่นก่อน ไม่ต้องติดตั้งอะไร

`preview/index.html` คือทั้งระบบย่อลงมาเหลือ **ไฟล์เดียว** เปิดจากมือถือได้เลย ไม่ต้องมีเซิร์ฟเวอร์
ไม่ต้องต่อเน็ต ข้อมูลจริงจาก v9.1 ทั้ง 1,449 ใบฝังอยู่ในไฟล์

```bash
python3 tools/build_preview.py     # สร้างใหม่จาก data/seed/*.json
```

* หน้าแรกให้เลือกว่าจะดูในมุมของใคร — กดชื่อแล้วทั้งหน้าจอเปลี่ยนตามสิทธิ์ของคนนั้น
* มีขั้นตอนแนะนำ 4 ขั้นที่กดแล้วสวมบทบาทให้เลย เพื่อดูว่าเงินหนึ่งก้อนเดินจากหน้างานถึงบัญชียังไง
* จอกว้างวางเป็นโทรศัพท์บนโต๊ะพร้อมคำอธิบายข้าง ๆ · จอมือถือแอปขึ้นเต็มจอทันที
* 7 หน้าจอ — งานของฉัน · สร้างใบเบิก · อนุมัติ · จ่ายเงิน · ตามเอกสาร · ภาพรวม · ค้นหา
* กฎบล็อก **B1 · B2 · B3 · B5 · B6 · B7 · B10** และธงเตือน **W1 · W5 · W9 · W10**
  พร้อม VAT · หัก ณ ที่จ่าย · รหัสอ้างอิงเดิม 10 หลัก ทำงานเหมือนฝั่งเซิร์ฟเวอร์
  (B7 — ไม่แนบสลิปการโอน กดบันทึกจ่ายไม่ได้)
* มีใบตัวอย่างติดป้าย “ตัวอย่าง” ไว้ 6 ใบ เพื่อให้กดอนุมัติ → จ่าย → รับเอกสาร ได้ตั้งแต่เปิดครั้งแรก
* สิ่งที่กดถูกจำไว้ใน `localStorage` ของเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ส่งออกไปไหน

**ตัวอย่างนี้ไม่ใช่ระบบจริง** — ไม่มีรหัสผ่าน ไม่มี 2FA ไม่มีไลน์ ไม่มี audit log ไม่มีฐานข้อมูลกลาง
ทุกคนที่เปิดลิงก์เห็นข้อมูลชุดเดียวกันและแก้ของตัวเองแยกกัน ใช้เพื่อดูว่าหน้าตาและกฎเป็นอย่างไรก่อนลงระบบจริง

## เริ่มใช้งานใน 3 คำสั่ง

```bash

npm run setup      # สร้างฐานข้อมูล + นำเข้าข้อมูลจากไฟล์ v8
```

## กฎที่ระบบบังคับให้

### กฎบล็อก — ผ่านไม่ได้

| รหัส | กฎ |
|---|---|
| B1 · B2 | ทุกบรรทัดต้องมีหมวดงานและประเภทต้นทุน |
| B3 · B4 | ต้องเลือกโครงการ อาคาร ผู้ขาย และระบุว่ามี VAT หรือไม่ |
| B5 | ผลรวมรายการย่อยต้องเท่ากับยอดหัวใบ และจำนวน × ราคาต้องเท่ากับจำนวนเงิน |
| B6 | ใบเกิน 5,000 บาท ต้องแนบไฟล์อย่างน้อย 1 ไฟล์ก่อนส่งขออนุมัติ |
| B7 | บันทึกการจ่ายต้องแนบสลิป |
| B8 | หมวดงานที่เลิกใช้/ยุบรวมไม่ปรากฏใน dropdown และเลือกไม่ได้ |
| B9 | ยอดเงินของใบที่จ่ายแล้วแก้ไม่ได้ตลอดกาล (แก้ได้เฉพาะอาคารและหมายเหตุ พร้อมเหตุผลลง `audit_log`) |
| B10 | เงินสดย่อยต่อรายการไม่เกิน 2,000 บาท และต้องเคลียร์บิลก่อนเติมเงิน |

### กฎเตือน — ผ่านได้แต่ติดธง (ผู้อนุมัติต้องกดทีละใบ)

W1 ผู้ขายรายใหม่ยังไม่เคยจ่าย · W2 ราคาสูงกว่าอ้างอิงเกิน 10% *(ปิดสวิตช์ไว้)* ·
W3 ผู้ขายค้างเอกสารเกิน 3 ใบ · W4 มีเครดิตค้างกับผู้ขายรายนี้ ·
W5 รายการซ้ำ (วันเดียวกัน **อาคารเดียวกัน** ยอดตรงกัน) · W6 ยอดซ้ำภายใน 7 วัน ·
W7 ใบของผู้อนุมัติเอง · W8 เกินงบอาคาร · W9 ยอดลงท้าย 000 และเกิน 20,000 ·
**W10 จ่ายให้ทีมงานของเราเอง** *(เพิ่มจาก v9 — ดูหัวข้อถัดไป)*

> **W2 ถูกปิดสวิตช์ไว้ตามสเปก §12** — ฟีเจอร์สร้างเสร็จแล้วแต่ยังไม่เปิด เพราะยังจับคู่วัสดุไม่ครบ
> เปิดได้ที่ **ตั้งค่า → สวิตช์ระบบ** เมื่อจับคู่วัสดุ 6 คู่ที่ค้างอยู่เสร็จ

### กฎอัตโนมัติ

- VAT คำนวณตามวิธีที่เลือก (แยก: ×7% · รวมแล้ว: ÷1.07) และเก็บทั้งยอดก่อน VAT / VAT / ยอดรวมเสมอ
- หัก ณ ที่จ่าย = %ของผู้ขาย × **ยอดบรรทัดที่เป็นค่าแรงหรือค่าเช่าเท่านั้น** คิดจากฐานก่อน VAT
- รหัสอ้างอิงเดิม 10 หลักสร้างเอง (ผู้เบิก 1 + โครงการ 3 + อาคาร 3 + หมวดงาน 3) — คนพิมพ์เองไม่ได้
- วันเบิกใบแรก/ใบล่าสุด/ระยะเวลาของอาคาร คำนวณจากใบเบิกจริง ไม่ให้คนกรอก
- อายุเอกสารนับจากวันจ่าย — 15 วันเหลือง · 30 วันแดง
- ใบปิดรายการอัตโนมัติเมื่อ จ่ายแล้ว + ของมาครบ + เอกสารครบตามประเภท

## หลักการออกแบบ 10 ข้อ ทำที่ไหนในโค้ด

| หลักการ | ทำที่ |
|---|---|
| 1. ห้ามพิมพ์รหัสเอง | ทุกช่องรหัสเป็น `<select>` (`public/js/views/request-form.js`) |
| 2. ห้ามลบ ห้ามแก้ยอดที่จ่ายแล้ว | `FROZEN_STATUSES` ใน `server/rules.js` + ใบกลับรายการ `reversals` |
| 3. รหัสสั้น ไม่แบกความหมาย | `building_id` เป็น B001–B072 · คุณสมบัติเก็บเป็นคอลัมน์ |
| 4. ทุกค่าต้องรู้ที่มา | คอลัมน์ `value_source` ในทุกตารางหลัก + `confidence` A/B/C/D |
| 5. เพิ่มแกน ไม่เพิ่มโค้ด | `cost_code` (แกน 1) × `cost_type` (แกน 2) แทนการแตกรหัสใหม่ |
| 6. เทียบต้นทุนเฉพาะ design เดียวกัน | `GET /api/reports/cost-per-sqm` จัดกลุ่มตาม `design_code` เท่านั้น |
| 7. วันเริ่มสร้าง = วันเบิกใบแรก | คำนวณด้วย `MIN(request_date)` ไม่มีช่องให้กรอก |
| 8. แสดงเป็นยอดเงิน | หน้าเอกสารและ Dashboard เรียงตามบาท ไม่ใช่จำนวนใบ |
| 9. ตรวจซ้ำที่ระดับอาคาร | `evaluateFlags` W5/W6 จับคู่ด้วย `building_id` ไม่ใช่ `project_id` |
| 10. มือถือมาก่อน | CSS มือถือมาก่อน ปุ่มสูง 48px ปุ่มประเภทต้นทุน 52px |

## อนุมัติผ่านไลน์ (สเปก §8 S2)

COO กดอนุมัติจากห้องแชทได้เลย ไม่ต้องเปิดเว็บ — แต่ **ใบที่ติดธงเตือนไม่มีปุ่มอนุมัติในการ์ด**
เหลือแค่ปุ่มเปิดดูในระบบ ตามหลักเดียวกับหน้าอนุมัติบนเว็บ

### เปิดใช้งาน

1. สร้าง Messaging API channel ที่ [LINE Developers](https://developers.line.biz/) แล้วเอา
   channel secret กับ access token มาใส่ตัวแปรสภาพแวดล้อมข้างต้น
2. เปิดหน้า **ตั้งค่า → ไลน์** คัดลอก Webhook URL ไปวางในคอนโซล เปิด "Use webhook"
   และ**ปิด "Auto-reply messages"** ไม่งั้นข้อความตอบกลับจะซ้อนกัน
3. แต่ละคนกดปุ่ม **ไลน์** บนแถบบนสุด แล้วพิมพ์รหัส 6 ตัวที่ได้ส่งเข้าห้องแชทของ OA
   รหัสมีอายุ 15 นาที ใช้ได้ครั้งเดียว

**ทำไมต้องผูกบัญชีก่อน** — สเปก §8 กันกรณีส่งต่อการ์ดให้คนอื่นแล้วกดอนุมัติแทน
ระบบจึงรับคำสั่งเฉพาะจาก LINE user id ที่ผูกกับบัญชีในระบบแล้วเท่านั้น
ทุก request ที่เข้า webhook ถูกตรวจลายเซ็น `x-line-signature` ก่อนเสมอ

**ผูกได้ทางเดียวคือรหัสที่ส่งเข้า OA** — ไม่มีช่องให้กรอก LINE user id เอง
เพราะ id นั้นคือกุญแจตัดสินว่าใครสั่งอนุมัติได้ ถ้ากรอกเองได้ ใครที่ล็อกอินได้ก็กรอก id ของ COO
ทับไว้ก่อนได้ แล้ว COO จะผูกบัญชีตัวเองไม่ได้และกดอนุมัติจากไลน์ไม่ได้เลย
รหัสที่ส่งผ่าน OA พิสูจน์ความเป็นเจ้าของให้เอง เพราะ id มาจากฝั่งไลน์ในคำขอที่เซ็นลายเซ็นมาแล้ว
และฐานข้อมูลบังคับซ้ำอีกชั้นว่า LINE id หนึ่งผูกได้คนเดียว (unique index บน `users.line_user_id`)

### สิ่งที่ส่งเข้าไลน์

| เมื่อไร | ใครได้รับ | ได้อะไร |
|---|---|---|
| ส่งใบขออนุมัติ | ผู้อนุมัติทุกคนที่ผูกบัญชีแล้ว (ไม่ส่งกลับให้ผู้ขอเอง) | การ์ดยอดเงิน · ผู้ขอ · โครงการ · อาคาร · ผู้รับเงิน · รายการย่อย 3 บรรทัดแรก |
| อนุมัติ / ไม่อนุมัติ | ผู้ขอ | ผลและเหตุผล พร้อมลิงก์เปิดใบ |

ปุ่มในการ์ด: **[อนุมัติ]** กดแล้วจบในคลิกเดียว · **[ไม่อนุมัติ]** เปิดแป้นพิมพ์พร้อมเติมข้อความ
`ไม่อนุมัติ REQ-2609-0042: ` ให้พิมพ์เหตุผลต่อ (เหตุผลบังคับเหมือนบนเว็บ) · **[ดูรายละเอียด]** เปิดเว็บ

### ยังไม่ได้ตั้งค่าก็ใช้ระบบได้ครบ

ทุกข้อความถูกบันทึกลงตาราง `line_outbox` ก่อนเสมอ ถ้ายังไม่มี channel จะค้างสถานะ
**"ยังไม่ได้ตั้งค่า"** ให้เห็นว่าใครควรได้รับอะไร แล้วกด **ส่งข้อความที่ค้างอีกครั้ง**
ในหน้าตั้งค่าเมื่อผูก channel เสร็จ — ไลน์ล่มหรือส่งไม่ออกก็ไม่ทำให้การอนุมัติบนเว็บล้มเหลว

## ข้อมูลย้อนหลัง แยกจากข้อมูลใหม่เสมอ

รายการทั้ง 1,449 ใบถูกนำเข้าเป็นสถานะ **จ่ายแล้ว** และตั้ง `value_source = 'นำเข้าย้อนหลัง'`

- กรองแยกได้ทุกหน้าจอ (ตัวกรอง "ที่มาของค่า")
- ในรายการใบเบิก ใบนำเข้ามีแถบเทาด้านซ้าย
- ระดับความเชื่อถือ **C** (672 ใบ · 7.63 ล้านบาท) **C2** (163 ใบ) และ **D** (1 ใบ) แสดงด้วยสีต่าง พร้อมคำว่า "ประมาณ"
  เพราะการแยกค่าของ/ค่าแรงในระดับเหล่านี้เป็นการอนุมาน ไม่ใช่ข้อเท็จจริง
- **หน้า "งานของฉัน" ซ่อนข้อมูลนำเข้าไว้ก่อน** เพราะเป็นหน้างานที่กำลังเดินอยู่ ไม่ใช่ประวัติ — กดปุ่มเดียวเพื่อดูย้อนหลัง
- **เอกสารไม่ถูกนำเข้า** ตามสเปก §9 — หน้าตามเอกสารและตัวเลข "ของที่จ่ายแล้วยังไม่มา"
  จึงนับเฉพาะใบที่เกิดในระบบ ไม่รวมข้อมูลนำเข้า
- รายการที่ไม่มีรหัสอาคารในไฟล์ต้นทาง (194 ใบ) ถูกพักไว้ที่อาคารชื่อ **"ไม่ระบุอาคาร"** ของแต่ละโครงการ
  (`is_building = N` จึงไม่เข้าตัวหารต้นทุนต่อ ตร.ม.) — ย้ายเข้าอาคารจริงได้จากปุ่ม "แก้ข้อมูลประกอบ"

ส่งออกกลับเป็น CSV (UTF-8 + BOM เปิดใน Excel ได้เลย) ที่ **ตั้งค่า → ส่งออกข้อมูล**
ครอบคลุม 21 ตาราง รวมใบเบิก รายการย่อย การจ่าย เอกสาร ประวัติการแก้ไข ทะเบียนพนักงาน เส้นโค้งต้นทุน และฝั่งรายได้

## สิ่งที่ยังไม่ได้ทำ และเหตุผล

**ตามสเปก §11 (ตั้งใจไม่ทำใน V1)** — BOQ generator อัตโนมัติ · ฝั่งรายรับ/ค่าเช่า · ROI ต่ออาคาร ·
รายงานภาษีอัตโนมัติ (ระบบเตรียมข้อมูลให้ บัญชียื่นเอง) · ระบบใบสั่งซื้อ (PO) และการจับคู่ 3 ทาง · แอปติดตั้ง

**ต้องมี LINE channel ก่อนถึงส่งการ์ดออกได้** — โค้ดครบแล้ว รอแค่โทเคน
(ดู [อนุมัติผ่านไลน์](#อนุมัติผ่านไลน์-สเปก-8-s2))

**จุดที่ทำต่างจากสเปกเล็กน้อย พร้อมเหตุผล**

1. **การเงิน (ตั้ม) สร้างใบเบิกเองไม่ได้** — สเปก §3.1 ระบุสิทธิ์ของ FINANCE ไว้แค่
   บันทึกการจ่าย/แนบสลิป/บันทึกรับเงินคืน แต่ข้อมูลย้อนหลังพบว่าตั้มเคยเบิกเอง 17 รายการ 14,106 บาท
   ระบบทำตามสเปกไว้ก่อน ถ้าต้องการเปิดสิทธิ์ ให้เพิ่ม `'request.create'` ในบทบาท `FINANCE`
   ที่ `server/auth.js` (มีคอมเมนต์กำกับไว้แล้ว)
2. **ประเภทต้นทุนมี 4 ปุ่ม ไม่ใช่ 3** — สเปก §5.1 กำหนดค่าคงที่ 4 ค่า (ของ · แรง · เช่า · โสหุ้ย)
   แต่ภาพหน้าจอ §8 วาดไว้ 3 ปุ่ม ระบบใช้ 4 ปุ่มตามโครงสร้างข้อมูล
   (ค่าน้ำมัน ค่าส่งของ ค่าเดินทาง ค่าสาธารณูปโภคในข้อมูลจริงเป็นโสหุ้ย ไม่มีปุ่มให้เลือกไม่ได้)
3. **มีประเภทต้นทุนที่ห้าคือ "ไม่ระบุ"** ใช้ได้เฉพาะข้อมูลนำเข้าย้อนหลัง 995,193 บาท
   ที่ไฟล์ v8 ยังแยกไม่ได้ (ระดับ D) — เลือกไม่ได้ในใบใหม่ และไม่อยู่ใน dropdown
4. **รหัส `NA` (ไม่ระบุ) ถูกตั้งเป็น "เลิกใช้"** เพราะไม่ใช่หมวดงานจริง ทำให้เหลือหมวดงานที่ใช้ต่อ 29 รหัสพอดีตามสเปก §5.1
5. **รหัส `TRK`** ที่สเปก §5.1 ระบุว่าให้เลิกใช้ ไม่มีอยู่ในไฟล์ต้นทาง จึงไม่ได้สร้างขึ้นมา
6. **บทบาท SERVICE ไม่ได้ใช้แล้ว** — v9 เปลี่ยนจตุพรและเต้เป็น PM เต็มตัว โค้ดยังรองรับบทบาทนี้อยู่เผื่อกลับมาใช้
7. **ธง W10 เป็นกฎที่เพิ่มเอง** ไม่ได้อยู่ในสเปก §6.2 — เพิ่มเพราะ v9 §25 เพิ่งพบว่ามีการจ่ายให้ทีมงานของเราเอง
   ถ้าไม่ต้องการ ปิดได้โดยลบบล็อก W10 ใน `server/rules.js`

## ตัวเลขวัดความสำเร็จ

ภาพรวม → แท็บ **"การใช้ระบบ"** แสดงตัวเดียวที่สเปก §10 กำหนดไว้:

> **% ของใบเบิกที่ผ่านระบบ ไม่ใช่ผ่านไลน์**
> เดือนแรก 60% · เดือนสาม 95% = สำเร็จ
> เดือนสามยัง 40% = ระบบใช้ยากเกินไป ต้องแก้ที่ระบบ ไม่ใช่ตำหนิคน
